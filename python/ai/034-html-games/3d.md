理解网页 3D，可以从下面这条主线开始：

几何模型 → 材质与贴图 → 骨骼与动画 → 光照与渲染 → 物理与碰撞 → 用户交互。

这些系统相互配合，但职责不同：模型决定物体的形状，贴图和材质决定它看起来是什么，骨骼决定角色怎么动，光照决定它如何被照亮，物理与碰撞则决定物体如何运动、接触和响应。

## 一、网页 3D 的技术栈

网页 3D 通常不是单一技术，而是由浏览器底层能力、3D 引擎、模型资源和业务代码组成。

业务交互层

点击、拖拽、选中、相机控制、动画状态

3D 引擎层

场景管理、模型加载、材质、动画、光照、射线检测

Three.js / Babylon.js

图形 API 与着色器

WebGL 或 WebGPU、顶点处理、像素着色、GPU 渲染

浏览器与 GPU

把 3D 场景计算并绘制到网页画布上

常见技术各有分工：

| 技术                      | 作用                        |
| ----------------------- | ------------------------- |
| HTML / CSS              | 网页布局、按钮、菜单、信息面板           |
| JavaScript / TypeScript | 场景逻辑、输入事件、状态管理            |
| WebGL                   | 使用 GPU 绘制实时 2D / 3D 图形    |
| WebGPU                  | 较新的 GPU 编程与图形计算接口         |
| Three.js                | 简化场景、相机、模型、材质和渲染器等操作      |
| Babylon.js              | 提供 3D 引擎、物理、动画和场景工具       |
| glTF / GLB              | 用于传输 3D 模型、材质、骨骼和动画等资源的格式 |

对于多数网页 3D 项目，使用 Three.js 或 Babylon.js 往往比直接从 WebGL 着色器开始更高效。

### 1. 几何体与 Mesh

电脑并不知道一个物体天然是椅子、汽车还是人。它首先处理的是几何数据。

一个常见的 3D 网格（Mesh）由这些信息构成：

| 概念         | 含义                     |
| ---------- | ---------------------- |
| Vertex（顶点） | 空间中的一个点，通常有 X、Y、Z 坐标   |
| Edge（边）    | 连接两个顶点的线               |
| Face（三角面）  | 构成物体表面的基本多边形，实时渲染常用三角形 |
| Normal（法线） | 表示表面朝向，用于光照计算          |
| UV         | 把模型表面的位置对应到二维贴图坐标      |
| Index（索引）  | 用来复用顶点、组织三角形的数据        |

例如，一个立方体可以用 8 个几何角点表示，但渲染时还需要三角形组织方式，以及法线、UV 等数据，才能正确呈现表面和材质。

多边形数量不是越多越好。 低面数模型更轻、更适合大量重复物体；高面数模型可以表达更复杂的几何细节，但会增加渲染、加载和内存成本。

### 2. 模型、网格和场景对象有什么区别？

这些词容易混用，但可以这样理解：

* Geometry：几何数据，描述形状。

* Mesh：通常指可渲染的网格对象，由几何数据和材质组成。

* Model：一个更宽泛的概念，可以包含多个 Mesh、节点层级、材质、骨骼和动画。

* Scene：容纳多个物体、相机、灯光等对象的整体空间。

例如，一辆汽车模型可以由车身、四个轮子、玻璃和车灯等多个 Mesh 组成。每个物体可以单独设置材质，也可以按照父子层级组织起来。

glTF 格式就能够保存网格、节点层级、材质、相机、骨骼和动画等场景资源。 【turn664738search2】

### 3. 坐标、变换和相机

每个 3D 物体通常有三个核心变换：

* Position：位置。

* Rotation：旋转。

* Scale：缩放。

物体可以有自己的局部坐标系。比如汽车的轮子相对于汽车车身有一个位置，汽车整体再相对于整个场景有另一个位置。这就是父子层级和坐标变换的用途。

### 1. 什么是骨骼（Skeleton）？

骨骼是一组具有层级关系的关节或骨骼节点。常见的角色骨架类似人体结构：

```
Root（根节点）
 └── Hips（骨盆）
      ├── Spine（脊柱）
      │    ├── Chest（胸部）
      │    │    └── Neck（颈部）
      │    │         └── Head（头部）
      │    ├── LeftArm（左臂）
      │    └── RightArm（右臂）
      ├── LeftLeg（左腿）
      └── RightLeg（右腿）
```

骨骼之间存在父子关系。旋转上臂时，前臂和手通常也会跟着移动；旋转根节点时，整个角色可以一起移动。

### 2. 什么是 Rigging 和 Skinning？

只有骨骼还不够，因为骨头本身不一定就是用户看到的皮肤和衣服。

Rigging（绑定） 是为模型建立骨架、控制器和关节关系的过程。

Skinning（蒙皮） 是将网格顶点与骨骼关联，使骨骼运动时模型表面跟着变形的过程。

每个顶点可以受到多个骨骼影响，并通过权重决定每根骨骼对该顶点的影响程度。例如，肘关节附近的顶点可能同时受到上臂和前臂骨骼影响，因此手臂弯曲时不会简单地沿关节处断开。

Three.js 的 `SkinnedMesh` 通过骨骼以及顶点的骨骼索引、权重来实现这类动画。 【turn941304search3】

### 3. 动画是如何工作的？

通常，动画资源包含多个关键帧：

| 时间    | 左臂旋转角度 |
| ----- | ------ |
| 0 秒   | 0°     |
| 0.5 秒 | 45°    |
| 1 秒   | 90°    |

动画系统根据当前时间计算目标姿态，并在关键帧之间插值，得到连续运动。

常见动画有：

* Idle：待机。

* Walk / Run：走路、跑步。

* Jump：跳跃。

* Attack：攻击。

* Sit / Stand：坐下、站起。

游戏中还会将不同动画切换或融合。例如，角色保持上半身瞄准，同时下半身播放跑步动画。

除了骨骼动画，还有 Morph Targets（形态目标），通过在多个顶点形态之间插值，实现面部表情、嘴型变化等效果。

需要注意：骨骼动画通常改变的是模型的变形状态，它不会自动建立物理碰撞，也不会自动阻止角色穿墙。

这是 3D 中非常重要的一组概念：贴图是数据，材质决定如何解释这些数据。

### 1. 贴图（Texture）

贴图是二维图像或纹理数据，被映射到 3D 模型表面上。

模型的 UV 坐标负责告诉渲染器：模型表面的某个位置，应该采样贴图上的哪个位置。

常见贴图类型包括：

| 贴图                  | 主要用途          |
| ------------------- | ------------- |
| Base Color / Albedo | 决定表面的基础颜色     |
| Normal Map          | 模拟细小凹凸产生的光照变化 |
| Roughness Map       | 控制表面不同区域的粗糙程度 |
| Metallic Map        | 控制表面的金属属性     |
| AO Map              | 增强角落、缝隙附近的遮蔽感 |
| Emissive Map        | 表现表面自身发光的区域   |
| Alpha Map           | 控制透明度或镂空区域    |

举个例子，一个石墙模型可以共用一套几何形状，通过颜色贴图呈现石头颜色，通过法线贴图表现裂纹，通过粗糙度贴图表现不同区域的表面差异。

其中，法线贴图只是改变光照计算时使用的表面方向，不会真的改变模型轮廓，也不会自动影响碰撞形状。 【turn941304search0】

### 2. 材质（Material）

材质描述物体如何反射光、呈现颜色、表现透明度以及是否发光。

例如，同一个球体使用不同材质，可以分别表现为：

* 木球：非金属、较粗糙。

* 金属球：金属度高，具有明显反射。

* 塑料球：根据塑料类型呈现不同的粗糙度和高光。

* 玻璃球：涉及透明度、折射等更复杂的光学效果。

现代实时渲染通常大量采用 PBR（Physically Based Rendering，基于物理的渲染）材质工作流。以 Three.js 的 `MeshStandardMaterial` 为例，常用参数包括 `roughness`、`metalness`、`map` 和 `normalMap`。 【turn941304search0】

## 五、着色器、着色和光照：为什么物体会有明暗？

这三个概念紧密相关，但有所区别。

### 1. Shader（着色器）

着色器是运行在 GPU 上的程序，用于计算顶点的位置以及像素最终如何呈现。它可以用来计算颜色、光照、反射、透明度、扭曲和各种视觉效果。WebGL 的图形程序就包含 JavaScript 控制代码与 GPU 上运行的着色器代码。 【turn664738search4】

最常见的是：

Vertex Shader（顶点着色器）：处理顶点数据，常用于位置变换，以及传递后续着色需要的数据。

Fragment Shader（片元着色器）：计算片元的颜色或其他输出。一个片元可以理解为光栅化过程中产生的候选屏幕像素。

例如，一个简单的自定义片元着色器，可以让一个物体按屏幕位置显示渐变颜色；更复杂的着色器可以模拟水面、卡通描边、全息投影和玻璃折射。

### 2. 什么是 Shading（着色）？

着色是根据材质属性、表面方向、光线等信息，计算物体表面最终外观的过程。

例如，光照照到球体时：

* 朝向光源的区域可能更亮。

* 背对光源的区域可能更暗。

* 光滑表面可能出现锐利的高光。

* 粗糙表面则可能出现范围较大的柔和高光。

着色器是执行计算的程序，着色是这些计算产生视觉结果的过程。

### 3. Lighting（光照）

光照负责描述场景中的照明条件。它和材质、着色共同决定最终画面。

### 4. 阴影（Shadow）

阴影也不等于碰撞。典型的实时阴影计算，会判断光源视角下哪些区域被遮挡，再决定其他视角是否能看到这些位置的阴影。

例如，桌子可以在地面上投下阴影，但这并不能说明桌子是否具有物理碰撞体。

另外，实时阴影会增加 GPU 开销，因此在网页中经常需要限制投射阴影的灯光和物体数量。

## 六、碰撞检测与物理模拟：让物体遵守规则

这是网页 3D 和游戏开发中很重要的一部分。首先要区分两个概念：

碰撞检测（Collision Detection）负责判断物体是否发生接触或相交；物理模拟（Physics Simulation）还要计算碰撞之后物体应该如何运动。

### 1. 碰撞体（Collider）

### 2. 碰撞检测有哪些方式？

AABB（轴对齐包围盒）

使用不随物体旋转方向变化的矩形或长方体包围盒。它计算简单，适合快速判断两个物体是否可能相撞。

OBB（有向包围盒）

包围盒可以随物体旋转，形状拟合能力通常比 AABB 更好，但检测也更复杂。

网格碰撞

将物体表面上的三角形用于更精确的接触检测，适合复杂场景，不过代价通常较高。

射线检测（Raycasting）

从某个位置沿一个方向发出射线，判断射线与哪些物体相交。这常用于鼠标点击 3D 物体、准星瞄准、拾取以及地面检测。

需要注意：射线命中物体不等于完成了刚体物理模拟。Three.js 的 `Raycaster` 可以返回命中的对象、交点和距离等信息。 【turn941304search1】

### 3. 物理模拟（Physics）

物理引擎会维护物体的运动状态，并在每个模拟时间步中计算重力、速度、碰撞响应和约束等。

几个核心概念：

* Rigid Body（刚体）：描述物体的物理运动状态。

* Collider（碰撞体）：定义物体用于检测接触的几何形状。

* Gravity（重力）：持续影响物体运动。

* Friction（摩擦）：影响接触表面的相对滑动。

* Restitution（弹性系数）：影响碰撞后的反弹效果。

* Joint（关节）：约束两个物体之间的相对运动。

常见刚体类型包括：

| 类型        | 行为                  |
| --------- | ------------------- |
| Static    | 静态物体，例如地面、固定墙壁      |
| Dynamic   | 受力和碰撞影响，例如可以被推倒的箱子  |
| Kinematic | 由程序控制运动，例如按照脚本移动的平台 |

以一个人物走路的场景为例：

1. 键盘输入产生预期移动方向。

2. 控制器计算人物在本帧想移动多远。

3. 碰撞检测判断前方有没有墙壁、地面或台阶。

4. 控制器调整实际移动结果，避免人物直接穿过障碍物。

5. 3D 模型和骨骼动画根据最终移动状态更新。

这也是为什么角色控制器和普通刚体不完全相同：角色往往需要按玩家指令移动，并遵循游戏特定的走路、跳跃和台阶规则。

Rapier 是一个可用于 JavaScript / TypeScript 项目的实时物理引擎，支持刚体、碰撞体、接触事件和角色控制器等功能。 【turn941304search9】【turn941304search2】

## 七、用户交互：鼠标如何选中一个 3D 物体？

网页的 3D 画布本质上是一个渲染区域。浏览器收到鼠标点击事件时，并不知道用户想选中场景里的哪个模型。

因此，需要把二维鼠标坐标转换成对应相机视角下的一条三维射线，再进行射线检测。

鼠标点击

网页坐标 X、Y

坐标转换

转换为归一化设备坐标 NDC

相机发出射线

Raycaster 检查射线命中了哪些物体

执行交互逻辑

选中、显示信息、拖动、旋转或打开菜单

在 Three.js 中，核心代码大致如下：

JavaScript

```
const raycaster = new THREE.Raycaster();
const mouse = new THREE.Vector2();

function onPointerDown(event) {
  const rect = renderer.domElement.getBoundingClientRect();

  mouse.x = ((event.clientX - rect.left) / rect.width) * 2 - 1;
  mouse.y = -((event.clientY - rect.top) / rect.height) * 2 + 1;

  raycaster.setFromCamera(mouse, camera);

  const hits = raycaster.intersectObjects(
    scene.children,
    true
  );

  if (hits.length > 0) {
    console.log("选中的物体：", hits[0].object);
  }
}

renderer.domElement.addEventListener(
  "pointerdown",
  onPointerDown
);
```

这段代码展示的是基本拾取思路。实际项目还需要处理鼠标拖拽、滚动缩放、物体交互层、遮挡关系以及点击与拖拽的区别。

常见的网页 3D 交互有：

* Orbit Controls：旋转、平移和缩放相机。

* Object Picking：选择 3D 物体。

* Drag & Drop：移动、放置物体。

* Hover Highlight：鼠标悬停时高亮物体。

* Transform Controls：移动、旋转、缩放模型。

* WebXR：扩展到支持的虚拟现实和增强现实设备。

## 八、渲染后处理：让画面更有质感

除了模型、材质和灯光，很多网页 3D 效果还需要后处理（Post-processing）。

后处理通常是将已经渲染出的画面交给额外的图像处理步骤，再输出最终结果。

常见效果有：

| 效果             | 作用                    |
| -------------- | --------------------- |
| Bloom          | 让明亮区域产生柔和的光晕          |
| SSAO           | 模拟局部遮蔽，增强角落和物体接触处的深度感 |
| Depth of Field | 模拟景深和背景虚化             |
| Motion Blur    | 模拟运动模糊                |
| Color Grading  | 调整色调、对比度和整体视觉风格       |
| Anti-aliasing  | 减少边缘锯齿                |

但并不是所有视觉效果都需要后处理。例如，金属表面是否真实，主要还取决于材质、环境反射和光照；后处理无法弥补所有资源质量问题。

## 九、性能优化：为什么有的网页 3D 很流畅，有的很卡？

网页 3D 的性能通常受 CPU、GPU、模型大小、贴图占用、绘制调用次数以及物理模拟复杂度等因素影响。

重点优化方向包括：

模型优化。 减少不必要的三角形，使用合理的细节层级（LOD），远处物体使用低精度模型。

贴图优化。 控制贴图尺寸和数量，使用适当的纹理压缩格式。

减少绘制调用。 多个重复物体可以使用实例化渲染，避免为每个物体单独提交绘制工作。

简化碰撞。 使用胶囊体、盒体等简单碰撞体近似复杂渲染模型，减少物理计算压力。

优化光照和后处理。 限制实时阴影和高成本效果的使用范围。

异步加载与资源管理。 延迟加载暂时不可见的模型，离开场景时正确释放不再使用的 GPU 资源。

在资源文件方面，glTF / GLB 是网页 3D 常见的交付格式。它能够承载场景层级、模型、材质、贴图、骨骼和动画等数据；Three.js 的 `GLTFLoader` 也支持多种网格和纹理压缩相关扩展。 【turn664738search2】【turn664738search7】

此外，WebGL 仍是重要的网页 GPU 图形接口；WebGPU 提供了更现代的图形和通用 GPU 计算能力，但浏览器支持情况仍需要根据实际目标设备核对。 【turn664738search0】【turn664738search3】

## 十一、推荐的学习顺序

对于准备开发网页 3D 的人，建议按下面的顺序学习，而不是一开始就研究所有图形学细节。

1. Three.js 基础。 学会创建场景、相机、网格、灯光、渲染循环和相机控制。

2. 模型加载与材质。 使用 Blender 制作或获取 GLB 资源，理解 UV、贴图和 PBR。

3. 场景交互。 学习坐标转换、射线检测、鼠标拾取、拖拽和对象变换。

4. 骨骼和动画。 学会播放动画片段、切换动作，并将人物移动与动画状态关联起来。

5. 碰撞与物理。 选择 Rapier 等物理引擎，学习刚体、碰撞体、角色控制器和接触事件。

6. 渲染与性能进阶。 深入研究着色器、阴影、环境光照、后处理和资源优化。

可以从官方资源开始：Three.js 的 [官方文档](https://threejs.org/docs/)、[glTF 2.0 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html?utm_source=chatgpt.com)，以及 [Rapier JavaScript 指南](https://www.rapier.rs/docs/user_guides/javascript/)。

最重要的一点： 网页 3D 不是简单地把一个模型画出来，而是几何、材质、动画、光照、渲染和交互等多个系统协同工作的结果。先做出一个可以旋转和点击的模型，再逐步加入动画、碰撞与物理，是一条很实用的学习路线。
