# 聚宽研究环境兼容性指南

> 本文档记录 `etf_portfolio/` 在聚宽研究环境踩过的所有兼容性坑及解决方案。
> 适用于 `etf_portfolio/` 系列 notebook 和任何准备在聚宽运行的 Python 代码。

## 一、环境基线

| 组件 | 版本 | 备注 |
|------|------|------|
| Python | **3.6.7** | 远低于主流 3.9+，没有内置 dataclasses、match、walrus、内置泛型 |
| pandas | **1.1.5** | `resample("ME")` 还不存在，必须用 `"M"` |
| scipy | **1.2.0** | 较老 |
| scikit-learn | **0.19.2** | `LedoitWolf` 可用 |
| empyrical | < 0.5.x | `sortino_ratio` / `sharpe_ratio` **不接受 `risk_free=` kwarg** |
| matplotlib | 老 | 内部用 `obj[:, None]` 多维索引，老 pandas 不支持，会 `FutureWarning` 且只画一条线 |

> 关键结论：聚宽研究环境是 2020 年左右的版本快照，所有"新版本默认行为"都不能用。

## 二、Python 语法避坑

### 2.1 不要用 `from __future__ import annotations`（Python 3.7+）

聚宽 Python 是 3.6，导入这一行直接 `SyntaxError: future feature annotations is not defined`。

### 2.2 不要用 PEP 604 union 语法 `X | Y`（Python 3.10+）

包括：
- `pd.DataFrame | None` ❌
- `str | Path` ❌
- `Union[date, str]` ✅ 改用 typing.Union
- `Optional[pd.DataFrame]` ✅ 改用 typing.Optional

### 2.3 不要用 PEP 585 内置泛型（Python 3.9+）

- `list[str]` ❌ → `List[str]` ✅
- `dict[str, float]` ❌ → `Dict[str, float]` ✅
- `tuple[X, Y]` ❌ → `Tuple[X, Y]` ✅
- `set[X]` ❌ → `Set[X]` ✅

需要在文件头部 `from typing import List, Dict, Tuple, Set, Optional, Union, Iterable, Any`。

### 2.4 不要用 `@dataclass`（Python 3.7+）

聚宽 3.6 没有内置 `dataclasses` 模块。改成普通 class：

```python
class CandidateETFs(object):
    def __init__(self, kept, dropped, corr_matrix=None):
        self.kept = kept
        self.dropped = dropped
        self.corr_matrix = corr_matrix
```

构造调用不变，仍是 `CandidateETFs(kept=..., dropped=..., ...)`。

### 2.5 不要用 `typing.TypedDict`（Python 3.8+）

`TypedDict` 在 3.8+ 才有，聚宽 3.6 没有。改成普通 class 做 schema 提示（仅作文档用，运行时不影响）：

```python
# ❌ 老版本 ImportError
from typing import TypedDict
class BaselineHolding(TypedDict):
    code: str
    name: str
    weight: float

# ✅ 兼容
class BaselineHolding(object):
    def __init__(self, code, name, weight):
        self.code = code
        self.name = name
        self.weight = weight
```

实际数据仍用普通 dict 存储（`{"code": ..., "name": ..., "weight": ...}`），访问方式不变。

### 2.6 不要用 match/case（Python 3.10+）

### 2.6 walrus `:=` 可以用（3.8+）

### 2.7 f-string `{var=}` 调试语法不行（3.8+ 限定基础，3.13+ 才正式支持）

可以用基础 f-string：`f"x = {x}"`，不要用 `f"{x=}"`。

## 三、pandas 1.1.5 避坑

### 3.1 `resample("ME")` 报错，必须用 `"M"`

```python
# ❌ pandas 2.2+
monthly = prices.resample("ME").last()

# ✅ pandas 1.1.5
monthly = prices.resample("M").last()
```

老 pandas 的 DatetimeIndex 没有 `.freq`，要用 `pd.infer_freq()`。

## 四、empyrical 老版本 API 差异

### 4.1 `sharpe_ratio` / `sortino_ratio` 不接受 `risk_free` kwarg

```python
# ❌ 老 empyrical 报错
ep.sharpe_ratio(returns, risk_free=0.025)
ep.sortino_ratio(returns, risk_free=0.025)

# ✅ 兼容写法（用 inspect 动态判断）
import inspect

def _accepts_kw(func, kw_name):
    sig = inspect.signature(func)
    return kw_name in sig.parameters

def _call_with_optional_kw(func, returns, rf, kw_name):
    if _accepts_kw(func, kw_name):
        return func(returns, **{kw_name: rf})
    return func(returns)

sharpe  = _call_with_optional_kw(ep.sharpe_ratio, returns, rf, "risk_free")
sortino = _call_with_optional_kw(ep.sortino_ratio, returns, rf, "risk_free")
```

参见 `etf_portfolio/metrics.py`。

### 4.2 `calmar_ratio` 默认月频窗口（不同 empyrical 版本行为不一致）

我们自写的卡玛比率是路径依赖版本（基于训练窗口日收益），不依赖 `ep.calmar_ratio`。优化器中：

```python
def neg_calmar(w, returns_matrix, freq=252):
    port_ret = (returns_matrix.values * w).sum(axis=1)
    nav = np.exp(np.cumsum(port_ret))
    running_max = np.maximum.accumulate(nav)
    dd = (nav - running_max) / running_max
    mdd = float(-dd.min())
    ann_ret = float(port_ret.mean() * freq)
    return -ann_ret / max(mdd, 1e-6)
```

### 4.3 `sharpe_ratio` / `sortino_ratio` 的 `risk_free` 是**日频**利率（不是年化）

老版 empyrical 把传入的 `risk_free` 当成**日频**数字。如果传年化 0.025，每个交易日都减 0.025 → excess 几乎全是负数 → 算出超大负值（-50 ~ -400）。

**症状**：夏普列是 -50 / -80 / -400 这种量级的负数。

**修复**：调用前自己换算 `daily_rf = rf / 252`：

```python
# ❌ 传年化 rf（老 empyrical 当日频用，excess 全负）
ep.sharpe_ratio(returns, risk_free=0.025)

# ✅ 先换日频
daily_rf = rf / 252.0
ep.sharpe_ratio(returns, risk_free=daily_rf)
```

新版本 empyrical（>= 0.5.x）支持 `risk_free=年化` + `period='daily'`，但本项目代码统一用日频值，老新版本都能用。

## 五、matplotlib 老版本画图怪行为

### 5.1 多线 plot 只画一条线 + `FutureWarning: obj[:, None]`

**症状**：循环 `for col in df.columns: ax.plot(df.index, df[col])` 时只画出一条线，控制台报：

```
FutureWarning: Support for multi-dimensional indexing (e.g. `obj[:, None]`) is deprecated
```

**根因**：老 matplotlib 内部对 pandas Series 用 `obj[:, None]` 多维索引，老 pandas 不支持。

**修复**：把所有 Series 显式转 numpy 数组，DatetimeIndex 转 datetime 列表：

```python
# ❌ 报错
x_vals = nav_named.index            # Series
y_vals = nav_named[col]             # Series
ax.plot(x_vals, y_vals)

# ✅ 兼容
x_vals = nav_named.index.to_pydatetime()  # list of datetime
y_vals = nav_named[col].values            # numpy ndarray
ax.plot(x_vals, y_vals)
```

### 5.2 不依赖 `pf.create_full_tear_sheet`

`pyfolio 2.x` 与新 `empyrical` 不兼容（已知问题）。本项目只用 `empyrical` 直接算指标 + 自己出图，不调 `pf.*`。

## 七、聚宽研究环境专属注意事项

### 7.1 `from jqdata import *` 必须

聚宽内核 magic：`get_all_securities / get_price / get_security_info / get_index_stocks / finance.run_query` 等都必须先 `from jqdata import *` 才能用。

### 7.2 每个 notebook 顶部必须有 `from jqdata import *`

聚宽重启内存清空，每个 notebook 必须能独立从头跑（不依赖上一个 notebook 的内存对象，只依赖磁盘文件）。

### 7.3 通用模块不能依赖聚宽 magic

`etf_portfolio/*.py` 模块如果用 `get_price` 等聚宽函数，需要在函数体内调用（运行时），不能在 import 时执行。本项目用 `noqa: F821` 标注聚宽 magic 调用。

### 7.4 `finance.run_query` 单次最多 4000 行

不直接影响本项目，但写工具函数时要分页。

### 7.5 `get_price` 单次返回上限

研究环境不严格限速，但建议分批拉（< 100 只 ETF 一次即可）。

### 8.2 复权处理

ETF 用 `fq='pre'`（前复权）：

```python
df = get_price(code, end_date=..., count=..., frequency='daily',
               fields=['close'], skip_paused=False, fq='pre',
               panel=False, fill_paused=True)
```

### 8.3 `skip_paused=False, fill_paused=True` vs `skip_paused=True`

- `skip_paused=False`：保留停牌日，但 price/volume 都用停牌前收盘价（volume=0）
- `skip_paused=True`：直接跳过停牌日

策略回测建议 `skip_paused=True` + `fq='pre'`，避免噪声。

`/home/jquser/2026/<项目>/etf_portfolio/outputs/` 是聚宽研究环境的可写路径，跨 session 不持久，**每次重启要重跑**。

## 十一、模块五（资金与风险偏好面板）开发踩坑

模块五在 `06_资金与风险偏好面板.ipynb` 实施过程中发现了一批聚宽研究环境特有的运行时坑，与基础环境（Python 3.6 / pandas 1.1.5 等）无关，专门记录在此。

### 11.1 内存上限 1G（核心约束）

**症状**：北向资金 5 年累计 ~190 万行 `STK_HK_HOLD_INFO`，全量 `pd.concat` 会爆 OOM。

**解决**：流式按天循环 + 立即释放：
```python
df_prev = pd.DataFrame(columns=['code', 'share_number'])  # 仅持昨日快照
for day in pbar:
    chunk = finance.run_query(q)         # 当日 ~1500 行
    # ... 立即算 net_inflow ...
    df_prev = chunk[['code', 'share_number']].copy()
    del chunk; gc.collect()
```
**峰值内存 < 1 MB**（df_prev + 临时 merged + 累加 list）。

### 11.2 `tqdm` 在 Jupyter 里 print 一堆而不是进度条

**症状**：`from tqdm import tqdm` 在聚宽 Jupyter 里被包成"每次迭代 print 一行"，刷屏。

**解决**：用 notebook 版本，失败 fallback：
```python
try:
    from tqdm.notebook import tqdm
except ImportError:
    try:
        from tqdm.auto import tqdm
    except ImportError:
        from tqdm import tqdm
```

### 11.3 pandas 1.1.5 没有 `Rolling.rank()`

**症状**：`df.rolling(1260).rank(pct=True)` → `AttributeError: 'Rolling' object has no attribute 'rank'`。

**解决**：用 `apply` 自定义 helper：
```python
def rolling_rank_pct(series, window, min_periods=252):
    def _rank_last(x):
        if len(x) < min_periods:
            return np.nan
        return x.rank(pct=True).iloc[-1]
    return series.rolling(window=window, min_periods=min_periods).apply(_rank_last)
```

新版本 pandas（>= 1.4）原生支持 `Rolling.rank()`，但聚宽 1.1.5 不支持。

### 11.4 `get_index_valuation` 在某些账号/环境下不可用

**症状**：调用 `get_index_valuation('000985.XSHG', ...)` 报 `AttributeError: '...' object has no attribute 'get_index_valuation'`。

**解决**：用 `get_fundamentals` + `valuation.pe_ratio` 自组装成分股 PE 中位数：
```python
stocks = get_index_stocks(INDEX_CODE, date)
q = query(valuation.pe_ratio, valuation.pb_ratio).filter(
    valuation.pe_ratio != None, valuation.code.in_(stocks))
df = get_fundamentals(q, date)
# 25-75 分位过滤极端值
quantile = df.quantile([0.25, 0.75])
df_pe_valid = df['pe_ratio'][
    (df['pe_ratio'] > quantile['pe_ratio'].values[0]) &
    (df['pe_ratio'] < quantile['pe_ratio'].values[1])
]
pe_median = df_pe_valid.median()
```

`get_fundamentals` 是基础 API 一定有；`get_index_valuation` 在部分聚宽研究环境不存在。**注意**：市值加权 PE 与中位数 PE 数值不可直接对比，中位数 PE 更稳健（不受单只大权重股影响）。

### 11.5 `finance.run_query` 单次上限

研究环境实际限制是 **4000-5000 行/次**（不同账号可能有差异）：
- 两融 / 国债逆回购 数据量小，单次 run_query 足够
- 北向持股 `STK_HK_HOLD_INFO` 数据量大（5 年 ~190 万行），**必须按天循环** + 每次 1 个交易日 ≈ 1500 行
- 不能用 `run_offset_query`（要求旧版 API，新环境不一定支持），统一用 `run_query` 按日期分页

### 11.5.1 `bond.REPO_DAILY_PRICE` 的 date filter **不下推到数据库**

**症状**：cell 7 用 `bond.run_query(query(bond.REPO_DAILY_PRICE).filter(bond.REPO_DAILY_PRICE.date >= '2021-04-15'))` 拉 GC001 历史，本应返回 ~1300 行，实际只返回 **278 行**（约 1.1 年）。

**根因（双重叠加）**：
1. **`bond.REPO_DAILY_PRICE.date` filter 在聚宽研究环境下不下推到数据库**：filter 后实际仍返回全表数据。
2. **GC001 全量 4882 行超过 `run_query` 单次 4000 行上限**：结果被截断到 ~4000 行。
3. **不能用 `run_offset_query` 分页**（要求旧版 API，新环境不一定支持）。
4. **实测：用 `name == 'GC001'` 单独 filter 拉到 4882 行**（未超 4000 上限），证明只要先按 name 过滤就能避免被截断。

**修复方案**：**先按 name 拉全量**，再在内存里按 date 过滤：

```python
# ❌ date filter 不下推 + 全量超 4000 行 → 数据截断
df = bond.run_query(query(bond.REPO_DAILY_PRICE).filter(
    bond.REPO_DAILY_PRICE.date >= '2021-04-15'
))
# df 只有 278 行（被截断）

# ✅ 先按 name 过滤（缩小到 4882 行，未超 4000 上限），再内存按 date 过滤
df = bond.run_query(query(bond.REPO_DAILY_PRICE).filter(
    bond.REPO_DAILY_PRICE.name == 'GC001',
))
df['date'] = pd.to_datetime(df['date'])
df = df[df['date'] >= pd.Timestamp('2021-04-15')].copy()
# df 有 1300+ 行
```

**经验法则**：拉 `bond.*` / `finance.*` 表时，**先按高基数字段（name/code）过滤，再用低基数字段（date）内存过滤**，避免 date filter 不下推导致数据截断。

**聚宽各期限逆回购历史深度参考**（2026-09-15 实测）：

| 品种 | name | 行数 | 日期范围 |
|---|---|---|---|
| GC001（1天上交所）| `'GC001'` | 4,882 | 2006-08-16 ~ 2026-09-15 |
| GC002 | `'GC002'` | 3,853 | 2006-11-06 ~ 2026-09-15 |
| GC007（7天上交所）| `'GC007'` | 4,881 | 2006-08-16 ~ 2026-09-15 |
| GC014 | `'GC014'` | 4,121 | 2006-08-23 ~ 2026-09-15 |
| GC028 | `'GC028'` | 3,988 | 2006-08-23 ~ 2026-09-15 |
| R-001~R-028（深交所）| `'R-XXX'` | 3,641-3,645 | 2005-01-04 ~ 2026-09-15 |

GC007 数据量与 GC001 相同，可以无缝替换。

### 11.6 `bond.REPO_DAILY_PRICE` 字段：必须用 `name` 过滤 GC001

### 11.8 聚宽研究环境**没有**中长期利率 API（已查证）

下面这些"教科书上的利率指标"在聚宽研究环境**全部缺失**，做股债利差（ERP）必须用代理：

| 期望 API | 聚宽现状 |
|----------|----------|
| 10 年国债到期收益率 | ❌ 无 |
| 国债期货价格（T9999.CCFX）| ❌ 无（`bond` 模块没有期货表） |
| SHIBOR / DR007 | ❌ 无（`macro` 模块无相关表） |
| 中债收益率曲线 | ❌ 无 |

**唯一可用的"利率"**：`bond.REPO_DAILY_PRICE`（GC001，1 天期国债逆回购）。

**GC001 的缺陷**：
- 日度波动范围 1.45%-5.39%（与真实 10 年国债 2.5%-3.5% 区间严重不符）
- 有周期性波峰波谷（季末/节假日效应）
- 与股票市场相关性弱，**用于 ERP 计算噪声大**

**实际可行的 ERP 利率代理方案**：
1. GC001 + 60 日滚动均值（平滑周期波动，趋势可看，绝对值仍偏）
2. 国债 ETF `511260.XSHG` 价格 → 计算 N 日年化收益率（趋势代理，绝对值不可用）
3. 自备 10 年国债收益率 CSV（Wind / 中债登下载，最准确但需手动维护）

### 11.9 期货价格不能用"价格减 100"反推利率

**反例**：用户曾问能不能用 `100 - T9999.CCFX.close` 当利率。

**为什么不行**：期货价格和收益率是**非线性反相关**，中间还有转换因子（CF）、最便宜交割债券（CTD）、票面利率等参数。

| 期货价格 | 实际 10Y 国债收益率 | `100 - 价格` |
|----------|---------------------|--------------|
| 105.00 | 约 2.15% | -5 ❌ |
| 100.00 | 约 3.00% | 0 ❌ |
| 95.00 | 约 4.00% | 5 ❌ |

期货价格只能用作**方向代理**（价格涨→利率跌），不能直接当利率使用。

### 11.11 `datetime.date` 没有 `.date()` 方法

**症状**：`AttributeError: 'datetime.date' object has no attribute 'date'`。

**根因**：`pd.Timestamp.date()` 把 Timestamp 转成 `datetime.date`；后续 `datetime.date + pd.Timedelta()` 仍是 `datetime.date`，**不能再调 `.date()`**（那是 `datetime.datetime` 才有的）。

```python
history_max_date = df_history.index[-1].date()        # pd.Timestamp → datetime.date
calc_start_date = history_max_date + pd.Timedelta(days=1)   # 仍是 datetime.date
print(f"...{calc_start_date.date()}...")              # ❌ datetime.date 没有 .date()
print(f"...{calc_start_date}...")                     # ✅ 直接打印就是 YYYY-MM-DD
```

### 11.13.2 df_signals / risk_score 中的 NaN 信号值处理

**症状**：cell 11 的 `risk_contrib(row)` 函数遇到 NaN 信号值报 `KeyError: nan`：
```python
# 原代码
mz = {1: 1.0, 0: 0.5, -1: 0.0}[row['两融_5年分位_信号']]
# 报错：KeyError: nan
```

**触发场景**：
- df_module5 早期（分位起步段）：5 年分位前 1260 个交易日是 NaN
- df_module5 后期（2024-08 后北向按季度披露）：北向分位在季度跳跃日期是 NaN

**修复**：
```python
def risk_contrib(row):
    s_mz = row['两融_5年分位_信号']
    s_nb = row['北向_20日累计_1年分位_信号']
    s_er = row['ERP_5年分位_信号']
    if pd.isna(s_mz) or pd.isna(s_nb) or pd.isna(s_er):
        return np.nan                       # 任一信号为 NaN → 综合得分 NaN
    mz = {1: 1.0, 0: 0.5, -1: 0.0}[s_mz]
    nb = {1: 0.0, 0: 0.5, -1: 1.0}[s_nb]
    er = {1: 0.0, 0: 0.5, -1: 1.0}[s_er]
    return (mz + nb + er) / 3.0 * 100
```

或者更简洁用 dict.get（找不到 key 返回默认值）：
```python
def risk_contrib(row):
    mz = {1: 1.0, 0: 0.5, -1: 0.0}.get(row['两融_5年分位_信号'], np.nan)
    nb = {1: 0.0, 0: 0.5, -1: 1.0}.get(row['北向_20日累计_1年分位_信号'], np.nan)
    er = {1: 0.0, 0: 0.5, -1: 1.0}.get(row['ERP_5年分位_信号'], np.nan)
    if pd.isna([mz, nb, er]).any():
        return np.nan
    return (mz + nb + er) / 3.0 * 100
```

**风险**：如果用 `df_signals.apply(risk_contrib, axis=1)` 对全 df_signals 计算，**早期 NaN 行**会让整个 apply 失败。修复后只让对应行的 risk_score 为 NaN，不影响其他行。

### 11.15 聚宽研究环境"当前日期"反映真实当天，但部分数据更新滞后

**正确的认知**（修正之前的错误结论）：
- 聚宽环境**不是**固定快照时间，**每次运行的"今天"都是真实当天**（2026-09-17 跑，datetime.now() 返回 2026-09-17）
- `get_trade_days(end_date=AS_OF)` 返回的最后一个交易日 = 聚宽环境的"今天"（如果该天是交易日）
- 如果之前 cell 4 增量缓存只到 2026-06-30，**说明上次跑是在 2026-06-30 前后**，不是环境被"冻结"了

**但部分表的数据更新滞后**：
- `get_trade_days` 能返回到 2026-09-17（最新）
- `STK_MT_TOTAL`（两融）能取到 2026-09-16（最新）
- `STK_HK_HOLD_INFO` 能取到 2026-09-16（**但 link_id=310001/310002 只到 2026-06-30**，310005 到 2026-09-16）
- `get_index_valuation` / `bond.REPO_DAILY_PRICE` 能取到最新

**实测的 link_id 数据深度**（2026-09-17 验证）：
| link_id | 含义 | 数据最新到 |
|---|---|---|
| 310001 | 沪股通（北向）| **2026-06-30**（滞后 3 个月）|
| 310002 | 深股通（北向）| **2026-06-30**（滞后 3 个月）|
| 310005 | 港股通（南下）| 2026-09-16（最新）|

**为什么 310001/310002 滞后**：聚宽研究环境可能对"沪深股通通"（北向）数据更新有延迟，港股通（南下）数据更新更及时。具体原因需要联系聚宽平台确认。

**对模块五的实际影响**：
- df_module5 inner join 后被最滞后的表限制（北向数据），**最新日期只能到 2026-06-30**
- 即使 AS_OF 改到 2026-09-17，模块五的"最新读数"日期仍是 2026-06-30
- cell 4 增量循环（2026-07-01 ~ 当前）会全部 `continue`（chunk=0），这是正常的
- CSV 缓存保留到 2026-06-30，**不要删**

**常见困惑**：
- 隔了几个月没跑 notebook → CSV 缓存停在历史日期（如 2026-06-30）
- 重跑 cell 4 增量 → 自动从 CSV 历史最大日期算到当前日期
- 但因为数据滞后，增量循环通常 `continue` 跳过全部天数，CSV 不更新

**最佳实践**：
- AS_OF 用 `date.today()` 简化代码（聚宽环境日期随真实时间更新）
- 接受"北向数据滞后 3 个月"是聚宽环境限制，**不要试图绕过**（绕过了数据也是错的）
- 等聚宽平台修复数据同步后，重跑 cell 4 增量会自动补齐

### 11.16 北向资金流式循环：缺失日期必须 reindex 补齐

**症状**：cell 4 用 `for day in get_trade_days(...): if len(chunk)==0: continue` 跑完后，df_north_daily 在 chunk 为空的交易日没有行（被 continue 跳过）。inner join 后这些日期消失，图表上看起来"折线"（某段缺失）。

**解决**：合并前用完整日期索引 reindex：
```python
all_new_days = pd.DatetimeIndex(new_days)            # 增量期间的所有交易日
df_new = df_new_raw.reindex(all_new_days)            # 缺失日填 NaN
df_north_daily = pd.concat([df_history, df_new]).sort_index()
```

这样 inner join 时缺失日期会显示为 NaN 断点，图表上能用 matplotlib 的断线方式呈现，比"缺数据点"更直观。
