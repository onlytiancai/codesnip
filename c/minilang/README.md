用c语言写一个小的语言解释器，支持加减乘除，支持变量定义和使用，类型只支持数字，整数和小数，每个语句用分号结尾，支持一些内置函数如，abs,round,sqrt等，编译错误给出友好提示，如语法错误，类型不匹配等，支持if和for，函数定义和调用，内置print函数可以调试，print支持字符串模板，比如print("hello {n}\n")，其中n是变量名。

可以用 C 语言实现一个小型解释型语言。我建议把它设计成一门简洁的脚本语言，暂时命名为 MiniLang，采用“词法分析 → 语法分析 → 语义检查 → 解释执行”的结构，而不是直接用字符串分割来执行代码。这样以后增加函数、循环、错误定位等功能时会容易很多。

## 1. 语言设计

### 支持的功能

| 功能     | 示例                                           |
| ------ | -------------------------------------------- |
| 整数和小数  | `let a = 10;`、`let b = 3.14;`                |
| 四则运算   | `let c = a + b * 2;`                         |
| 变量赋值   | `a = a + 1;`                                 |
| 内置数学函数 | `abs(-3);`、`sqrt(16);`、`round(3.6);`         |
| 条件判断   | `if (a > 10) { ... }`                        |
| 循环     | `for (let i = 0; i < 10; i = i + 1) { ... }` |
| 自定义函数  | `fn add(a, b) { return a + b; }`             |
| 函数调用   | `let c = add(10, 20);`                       |
| 调试输出   | `print("结果是 {c}\n");`                        |
| 语句结束符  | 每条普通语句以 `;` 结尾                               |
| 友好错误提示 | 显示错误类型、行号、列号和出错原因                            |

### 数值类型

先只支持 `int` 和 `float` 两种数字类型：

- `int`：整数，例如 `10`、`-5`。
- `float`：小数，例如 `3.14`、`0.5`。
- `int` 和 `float` 可以参与同一算术表达式，结果按规则提升为小数。
- `if` 的条件必须是布尔表达式；比较运算产生布尔值，但不需要允许用户直接定义布尔变量。
- 除零、未定义变量、参数数量错误等问题都应给出明确的提示。

字符串仅用于 `print` 等需要字符串的场景，不作为普通变量类型。字符串模板中的 `{n}` 用于读取变量 `n` 的值。

## 2. 推荐的解释器结构

建议使用纯 C（C11），不依赖第三方库，先实现单文件版本 `minilang.c`。

源代码

let x = sqrt(16) + 2;

词法分析 Lexer

识别数字、标识符、关键字、运算符

语法分析 Parser

递归下降解析器，生成 AST 抽象语法树

语义检查与解释执行

变量作用域、类型检查、函数调用、控制流

输出结果或友好错误

其中有几个实现细节值得提前确定：

- 表达式优先级：乘除高于加减，括号优先，支持一元负号。
- 变量作用域：函数有自己的局部作用域，可以读取外层全局变量；函数参数与局部变量不能意外覆盖全局变量。
- 函数调用：统一处理用户定义函数和内置函数，检查参数个数及类型。
- 控制流：`if`、`for` 和 `return` 通过解释器的执行状态处理。
- 错误诊断：每个 Token 和 AST 节点记录行列号，便于定位错误。
- 模板输出：`print("hello {n}\n");` 先解析模板，再查找变量并格式化数值；未知变量应提示错误，而不是静默输出。

## 3. 示例程序

这门语言最终应当能够执行类似下面的程序：

```
fn factorial(n) {
    if (n <= 1) {
        return 1;
    }

    return n * factorial(n - 1);
}

let total = 0;

for (let i = 1; i <= 5; i = i + 1) {
    total = total + i;
}

let result = factorial(5);

print("1 到 5 的和：{total}\n");
print("5 的阶乘：{result}\n");
print("绝对值：{abs(-12)}\n");
print("平方根：{sqrt(81)}\n");
print("四舍五入：{round(3.6)}\n");
```

预期输出：

```
1 到 5 的和：15
5 的阶乘：120
绝对值：12
平方根：9
四舍五入：4
```

这里的 `return` 结束当前函数，递归调用也应该正常工作。

## 4. 错误提示示例

解释器不应该只输出 `Syntax error` 或直接崩溃，而应尽可能说明原因。

语法错误

第 2 行，第 10 列

`let x = 10 + ;`

错误：缺少表达式，运算符 `+` 后面需要一个数字、变量或括号表达式。

未定义变量

第 3 行，第 12 列

`let x = price + 1;`

错误：变量 `price` 尚未定义。

参数类型错误

第 4 行，第 9 列

`sqrt("abc");`

错误：函数 `sqrt` 的第 1 个参数必须是数字，实际传入了字符串。

## 5. 实现时还需要注意的规则

1. `sqrt(-1)`、除零和超出数值范围都需要有明确的运行时错误处理。
2. `round` 应明确采用哪种舍入规则，避免不同平台行为不一致。
3. `for` 的初始化、条件和更新表达式之间用逗号分隔，而每个完整的普通语句以分号结束。
4. 函数定义和 `if`、`for` 代码块本身不要求在右花括号后加分号。
5. 需要限制递归深度和循环执行次数，避免错误程序导致栈溢出或解释器无限运行。

我的建议是先实现一个完整的单文件版本，再逐步拆分成 `lexer.c`、`parser.c`、`ast.c`、`interpreter.c` 和 `main.c`。 这样既容易编译调试，也方便未来增加字符串、数组、模块和更多内置函数。

需要说明的是，上面给出的是设计方案和目标示例，还不是可以直接编译运行的完整解释器源码。完整实现需要把词法分析、AST、作用域、函数调用和错误处理等模块真正连接起来。

### 7. 编译与运行

Linux、macOS 或安装了 GCC 的环境中执行：

```
gcc -std=c11 -Wall -Wextra -O2 minilang.c -lm -o minilang
```

创建一个 `demo.ml` 文件：

```
fn factorial(n) {
    if (n <= 1) {
        return 1;
    }
    return n * factorial(n - 1);
}

let sum = 0;

for (let i = 1; i <= 5; i = i + 1) {
    sum = sum + i;
}

let result = factorial(5);
let root = sqrt(81);

print("sum = {sum}\n");
print("factorial = {result}\n");
print("sqrt = {root}\n");
```

运行：

```
./minilang demo.ml
```

输出：

```
sum = 15
factorial = 120
sqrt = 9
```

### 8. 当前版本的限制

这是一个轻量级的基础实现，还不是完整的静态类型检查器。需要特别说明：

- `print` 模板目前支持 `{变量名}`，例如 `{sum}`；不支持在模板内直接写 `{sqrt(81)}` 这样的表达式。可以先将函数结果赋给变量再输出。
- 普通变量只支持数字；字符串仅用于 `print`。
- 错误检查主要在解析或执行时进行，尚未实现独立的完整语义分析阶段。
- 为控制实现规模，单个代码块最多支持 128 条直接语句，变量、Token、函数和递归也有数量上限。
- 编译器可能对函数名长度给出截断警告，但不影响上面的演示程序运行；建议后续进一步统一标识符长度限制并完善内存清理。

这份代码适合作为解释器的第一版。下一步最值得做的是增加独立的语义检查阶段，在运行前检查未定义变量、重复定义、函数参数数量及类型错误，让脚本在执行之前就能获得更完整的诊断信息。
